# OP Embedded Studio 项目功能梳理

> 文档性质：内部产品与技术分析
> 梳理日期：2026-08-27
> 依据：项目 README、公开文档、应用入口、嵌入式功能源码、固件源码与测试目录

## 1. 执行摘要

OP Embedded Studio 是一套面向 ESP32 显示设备的嵌入式 UI 设计、交互原型和内容部署平台。项目基于 OpenPencil 的设计编辑器能力发展而来，在完整矢量画布、Figma 文件兼容、AI、CLI、MCP 和 SDK 的基础上，增加了真实屏幕适配、RGB565 内容烘焙、设备交互状态机、USB/BLE 内容传输、固件兼容检查和自动更新等能力。

项目的核心闭环是：

```text
设计界面
  → 组织交互
  → 设备模拟预览
  → RGB565 内容烘焙
  → 检查或更新固件
  → USB/BLE 传输
  → 真机验证
```

它不是简单的图片烧录工具，也不只是通用设计编辑器。其核心价值是把传统上分散在设计师、前端工具、嵌入式转换脚本和 ESP-IDF 工程中的流程，收敛到一个可视化工作台中。

当前最成熟的主流程是：

> Frame/图片设计 → 交互编排 → 设备预览 → USB 自动检查固件 → 内容传输。

从产品阶段判断，项目已经超过概念验证阶段，具备真实设备内容部署能力，但仍处于工程化产品打磨期。下一阶段的主要挑战是设备可靠性、交互方案持久化、通用运行时屏幕配置、硬件自动验收和动态数据绑定。

## 2. 产品定位

### 2.1 一句话定位

面向 ESP32 屏幕设备的可视化 UI 原型和内容部署平台，同时提供完整设计编辑与 AI 自动化能力。

### 2.2 产品能力分层

项目可分为三层核心能力：

1. **设计工具**：创建和编辑嵌入式 UI，支持矢量图形、文本、组件、变量、自动布局和 `.fig` 文件。
2. **设备原型工具**：把多个画面组织成事件驱动的交互状态机，并在设备模拟器中验证。
3. **部署工具**：把设计转换为 RGB565 内容，检查设备固件，通过 USB 或 BLE 写入 ESP32。

此外还包含 AI、CLI、MCP、Vue SDK、协作和本地优先存储等横向能力。

### 2.3 当前能力边界

当前设备侧更接近“预渲染 UI 播放器与状态机运行时”，擅长：

- 显示预渲染画面。
- 根据触摸或 BOOT 事件切换状态。
- 播放 PNG 序列。
- 执行手动浏览、幻灯片和自定义跳转。

当前还不是完整的动态嵌入式应用运行时，尚未形成以下一等能力：

- 实时传感器数据绑定。
- 动态文本和数值更新。
- 控件局部刷新。
- 表单、滚动列表等运行时控件。
- 复杂条件和业务逻辑。
- 任意用户脚本。
- 完整 LVGL 控件树或业务工程生成。

## 3. 用户界面的五个核心工作区

应用右侧面板形成五条主要功能线。

| 工作区 | 主要用途 | 输入 | 输出 |
| --- | --- | --- | --- |
| 设计 | 编辑界面和图形属性 | Frame、图形、文本、组件 | 可编辑设计文档 |
| 代码 | 查看、导入或生成设计代码 | 当前选区、页面、HTML/JSX | JSX、HTML、Tailwind 或设计节点 |
| AI | 用自然语言设计和准备部署 | 文字、参考图、当前画布 | 设计修改、部署确认卡 |
| 交互 | 编排多画面状态机 | 多个 Frame、PNG 序列 | 设备交互定义 |
| 烧录 | 适配屏幕并传输内容 | Frame、图片、交互方案 | RGB565 内容及设备固件 |

### 3.1 设计工作区

设计工作区是一套完整的 CanvasKit 矢量编辑器，主要包括：

- 页面和图层树。
- CanvasKit/Skia 画布。
- 绘图和操作工具栏。
- 上下文属性面板。
- 多文档标签页。
- 缩放、标尺、吸附线、选区和悬停反馈。
- 撤销和重做。

用户既可以从零创建界面，也可以打开 `.fig`、`.pen` 文件，导入 HTML/CSS/Tailwind，或从 Figma 复制节点继续编辑。

### 3.2 代码工作区

设计与代码之间支持双向转换：

- 将设计表达为 JSX。
- 生成 Tailwind 风格代码。
- 输出独立 HTML。
- 将 HTML/CSS/Tailwind 转换为可编辑设计节点。
- 查看或比较 JSX 与当前设计结构。
- 通过兼容 Figma Plugin API 的 JavaScript 操作文档。

这一工作区可用于设计交付、前端代码生成和程序化构建设计。

### 3.3 AI 工作区

AI 不是普通问答助手，而是编辑器操作代理。它能够读取：

- 当前页面和选区。
- 节点树及节点属性。
- 当前屏幕方案。
- 可用设备画面。
- 已创建的交互方案。

它能够执行：

- 创建图形、文字、Frame、组件和页面。
- 修改填充、描边、效果、排版和布局。
- 管理组件、变量和模式。
- 分析颜色、字体、间距和重复结构。
- 导出图片、SVG、HTML、JSX。
- 通过截图进行视觉验证。
- 准备单屏部署方案。
- 准备手动浏览、幻灯片或自定义交互方案。

AI 与硬件之间存在明确的用户确认层：

```text
AI 理解需求
  → 修改设计或生成部署提案
  → 显示确认卡和设备预览
  → 用户明确确认
  → 请求 USB 设备权限
  → 执行固件检查和内容传输
```

AI 的“准备”和“预览”只生成主机侧内容，不直接操作硬件。

### 3.4 交互工作区

交互工作区负责内容逻辑和状态关系，不直接负责烧录。它管理：

- 多个交互方案。
- 每个方案的状态列表。
- 初始状态。
- 状态位置和连接端口。
- 状态间的事件跳转。
- 手动浏览顺序。
- 幻灯片播放间隔。
- PNG 序列的播放参数。

状态图支持：

- 从节点四边端口拖拽连接。
- 正交圆角连线。
- 符合条件的双向连接合并显示。
- 中键或滚轮平移。
- `Ctrl`/`Command` 加滚轮缩放。
- 触摸双指平移和缩放。
- 按住 `Z` 划过连线删除关系。
- 在底部配置事件和目标状态。

交互定义可以被设备模拟器、烧录页、AI 部署卡和内容烘焙器共同使用。

### 3.5 烧录工作区

烧录工作区负责设备执行，主要包含：

- 目标屏幕方案选择。
- 自定义屏幕方案管理。
- 屏幕分辨率预设 Frame 创建。
- Frame 内容烘焙。
- 本地图片、PNG 序列和视频输入。
- 画面适配及预览。
- 交互方案选择和烘焙。
- USB 传输。
- BLE 传输。
- 固件初始化和自动兼容检查。
- 实验性的 Wi-Fi 传输和实时镜像源码路径。

## 5. 嵌入式屏幕适配

### 5.1 内容烘焙

设计中的 Frame 或图片可按目标设备参数烘焙为 RGB565 内容，支持：

- 目标宽高和分辨率。
- 矩形屏与圆形可视区域。
- RGB/BGR 颜色顺序。
- 像素大小端。
- 显示偏移和方向相关配置。
- 背景补边。
- 内容分区容量检查。

### 5.2 画面适配模式

| 模式 | 行为 | 适用场景 |
| --- | --- | --- |
| 拉伸 | 完整填满目标区域，可能改变宽高比 | 设计稿比例与屏幕接近 |
| 等比缩放 | 保持宽高比完整显示，空白区域补背景色 | 不允许内容裁切 |
| 不缩放 | 保持源像素尺寸，超出时居中裁切，不足时补边 | 像素级界面或图标 |

USB、BLE、AI 单画面部署和交互部署共用同一套适配规则。

### 5.3 设备模拟器

设备模拟器用于在接触硬件前验证：

- 真实目标分辨率和宽高比。
- 圆形可视区域裁切。
- 图片缩放和居中逻辑。
- 背景补边。
- 当前交互状态。
- 触摸和 BOOT 事件跳转。
- 幻灯片播放和暂停。

## 6. 交互与动画能力

### 6.1 手动浏览

- 定义下一张和上一张对应的设备事件。
- 配置画面顺序。
- 配置首尾循环。
- 适用于菜单翻页、图片浏览和方案对比。

### 6.2 幻灯片

- 按指定间隔自动切换画面。
- 模拟器中支持暂停和重新开始。
- 适用于展示、轮播和动态信息屏。

### 6.3 自定义状态机

- 为每个状态定义触发事件和目标状态。
- 支持触屏单击、双击、三击、长按。
- 支持 BOOT 单击和长按。
- 适用于菜单、设备流程和状态演示。

### 6.4 PNG 序列与动画状态

- 导入至少两张 PNG 作为序列。
- 校验所有帧尺寸一致。
- 设置序列 FPS。
- 根据内容分区容量进行压缩和大小检查。
- 可将每个交互状态定义为独立 PNG 序列。
- 状态内部播放动画，设备事件可切换到另一段动画。

## 7. 设备传输与固件

### 7.1 USB 主流程

USB 是当前最完整的部署链路：

1. 选择设备方案和内容来源。
2. 设置画面适配方式和背景色。
3. 烘焙单画面、交互或序列内容。
4. 用户确认烧录并选择 USB 设备。
5. Studio 检查当前固件和内容协议兼容性。
6. 兼容时直接传输内容。
7. 不兼容时自动更新基础固件。
8. 等待设备重新枚举和连接。
9. 继续传输原先准备的内容。
10. 设备重启并加载新内容。

日常内容更新通常不需要重新编译和烧录完整应用固件。

### 7.2 BLE

- Chromium 浏览器通过 Web Bluetooth 连接。
- 支持单画面、交互状态机和 PNG 序列。
- 支持独立 Android BLE 图片上传器。
- 首次使用需获取操作系统蓝牙权限。

### 7.3 Wi-Fi 和实时镜像

Wi-Fi 内容传输和 Wi-Fi 实时镜像的源码、固件目录和适配器仍然存在，但当前属于实验性能力：

- 默认发布界面不展示。
- 不作为稳定产品承诺。
- 主要供底层固件、网络和镜像开发调试。

### 7.4 应用固件与用户内容分离

设备侧应用固件负责：

- 初始化屏幕、触摸、电源和按键。
- USB/BLE 通信。
- 读取内容分区。
- 显示 RGB565 内容。
- 执行状态机。
- 播放 PNG 序列。
- 上报设备能力和协议状态。

用户内容负责：

- 单张 RGB565 图片。
- 多状态画面。
- 状态跳转表。
- 幻灯片参数。
- PNG 序列帧。
- 动画状态定义。

这种分离使兼容设备可以只更新内容，而不必每次重刷应用固件。

## 8. 屏幕方案、固件方案和内容方案

| 概念 | 解决的问题 | 示例 |
| --- | --- | --- |
| 屏幕方案 | 屏幕规格和接线方式 | 360×360、圆屏、ST77916、QSPI |
| 固件方案 | 设备如何驱动硬件并接收内容 | USB 交互固件、BLE 序列固件 |
| 内容方案 | 此次设备展示什么 | 单画面、幻灯片、状态机 |

### 8.1 屏幕方案包含的信息

- 屏幕模块和驱动控制器。
- 分辨率和可视区域形状。
- SPI、I80、QSPI 等接口。
- RGB/BGR、大小端和坐标偏移。
- Flash、PSRAM 和内容分区容量。
- GPIO、FPC 引脚和接线说明。
- 内置固件清单关联。

### 8.2 自定义方案的边界

自定义屏幕方案可用于：

- 创建设备分辨率 Frame。
- 模拟设备可视区域。
- 进行 RGB565 编码。
- 计算内容容量。

但只有存在匹配的预编译固件时才能直接烧录。当前自定义方案不会自动生成新的显示驱动或固件。

## 10. AI、CLI、MCP 与 SDK

### 10.1 AI 模型与凭据

项目支持配置多模型和多供应商，包括：

- OpenAI。
- Anthropic。
- Google AI。
- OpenRouter。
- Z.ai。
- MiniMax。
- OpenAI-compatible。
- Anthropic-compatible。

模型配置、供应商连接、角色分配和凭据相互分离。凭据由统一凭据管理器保存，并在运行时按需解析。

### 10.2 CLI

CLI 可以：

- 查看文档信息、页面和节点树。
- 搜索节点并读取详细属性。
- 查看变量和集合。
- 导出 PNG、JPG、WEBP、SVG、HTML、JSX、PDF、PPTX 和 `.fig`。
- 导入 HTML/CSS/Tailwind。
- 分析颜色、排版、间距和重复结构。
- 检查设计一致性、结构和可访问性。
- 执行 Figma Plugin API 风格 JavaScript。
- 连接正在运行的桌面应用并控制当前文档。
- 以 JSON 输出供程序消费。

### 10.3 MCP

MCP 服务可让 Claude Code、Cursor、Windsurf 等客户端读写设计文档。工具覆盖：

- 读取和查询。
- 创建和修改。
- 页面和结构管理。
- 组件与变量。
- 矢量和布尔操作。
- 设计分析。
- 代码生成。
- 图片和资产导出。

### 10.4 Vue SDK 与程序化设计

- 提供无头 Vue 3 编辑器 SDK。
- 暴露编辑器上下文、画布、选区和命令模型。
- 提供属性面板 composable 和基础控件。
- 支持 JSX 构建设计节点。
- 支持设计导出为 JSX/Tailwind。
- 支持 DOM/CSS/HTML 与设计节点转换。

## 11. 协作、存储与桌面能力

### 11.1 协作

- 基于 WebRTC 的 P2P 协作。
- 基于 Yjs/CRDT 的并发合并。
- 实时光标、选区和在线状态。
- 跟随协作者视角。
- 加密随机房间 ID。
- IndexedDB 本地持久化。
- 无需中心业务服务器或账户。

### 11.2 存储与恢复

- 本地优先文档缓存。
- 自动保存。
- 崩溃和未保存文档恢复。
- 远程存储 provider 抽象。
- 后台同步和 outbox。
- S3-compatible 工作区能力。
- 远程绑定不取代本地文件身份。

### 11.3 桌面与 Web

- Vue 3 Web 应用。
- Tauri v2 桌面应用。
- macOS、Windows、Linux 构建。
- 原生菜单、文件对话框和系统文件关联。
- PWA 和移动端触摸界面。
- 桌面系统凭据库。
- 浏览器 WebCrypto 加密 IndexedDB 凭据存储。

## 12. 典型用户路径

### 12.1 静态设备界面

```text
选择屏幕方案
  → 按屏幕分辨率创建预设 Frame
  → 在画布中设计
  → 选择适配方式
  → 查看圆屏/方屏预览
  → USB 或 BLE 传输
```

适用于表盘、启动画面、仪表显示、状态页和静态信息屏。

### 12.2 可操作设备原型

```text
创建多个 Frame
  → 加入交互状态图
  → 定义触摸/BOOT 事件
  → 在设备模拟器测试
  → 烘焙全部状态和跳转表
  → 写入设备
```

适用于菜单、多级页面、参数切换、产品演示和设备流程验证。

### 12.3 图片序列和动画

```text
选择多张 PNG 或视频
  → 转换为统一尺寸帧
  → 设置 FPS
  → 检查内容分区容量
  → 传输序列
  → 设备循环播放
```

也可把多个 PNG 序列组织成动画状态机。

### 12.4 AI 生成和部署

```text
选择目标 Frame
  → 输入需求或提供参考图
  → AI 创建设计
  → AI 截图检查
  → AI 准备单屏或交互方案
  → 用户查看部署确认卡
  → 用户确认
  → USB 部署
```

## 15. 功能成熟度

### 15.1 可作为主要产品流程

- CanvasKit 设计画布。
- Frame、图片、文本和矢量编辑。
- 屏幕分辨率预设。
- RGB565 烘焙。
- 圆屏和矩形屏预览。
- USB 单画面传输。
- USB 交互内容传输。
- 固件协议检查和自动更新。
- BLE 内容上传。
- 手动浏览、幻灯片和自定义状态机。
- PNG 序列与动画状态。
- AI 设计和部署确认卡。
- 内置设备 profile。

### 15.2 已实现但依赖运行环境

- Web Serial：依赖 Chromium、操作系统和用户授权。
- Web Bluetooth：依赖浏览器、系统蓝牙能力和权限。
- Tauri 桌面原生能力。
- Figma `.fig` 高保真往返。
- Google Fonts 自动回退。
- P2P 实时协作。
- 远程存储同步。
- ACP 外部编码代理。

### 15.3 实验性或默认隐藏

- Wi-Fi 内容传输。
- Wi-Fi 实时镜像。
- 非内置屏幕的直接固件烧录。
- 完全运行时可配置的通用显示固件。
- 所有内置设备达到同等硬件验证级别。

### 15.4 明确限制

- 当前设备交互固件最多保存 10 个画面。
- 自定义 profile 不等于拥有匹配固件。
- 内容大小受 Flash 内容分区限制。
- 不支持 Web Serial/Web Bluetooth 的浏览器不能直接连接设备。
- 特殊设备可能需要专用电源、复位、TE 和触摸初始化。
- Figma 高级节点和少见视觉语义并非全部可编辑。
- Wi-Fi 路径当前不应作为正式交付承诺。

## 16. 已形成的核心资产

### 16.1 统一设计数据模型

人工编辑、AI、CLI、MCP、格式导入导出和 RGB565 烘焙都围绕统一 SceneGraph 工作，避免维护多套设计逻辑。

### 16.2 浏览器端高质量渲染

CanvasKit/Skia 让复杂文字、渐变、阴影、图片和矢量先在主机端完成栅格化，ESP32 只负责显示预渲染结果和执行有限交互逻辑。

### 16.3 通用设备内容运行时

设备固件已经具备：

- Frame 内容存储。
- USB 和 BLE 内容服务。
- 多状态交互运行时。
- 动画交互运行时。
- PNG 序列播放器。
- 屏幕驱动工厂。
- 输入事件处理。
- 多种 Flash 分区方案。

### 16.4 固件与内容协议协调

前端能够识别用户取消、Web Serial 不可用、串口占用、固件不兼容、协议版本不匹配、设备重连和内容失效等状态，并提供相应的恢复流程。

### 16.5 屏幕 profile 数据库

内置 profile 已经覆盖控制器、总线、颜色、偏移、GPIO、接线、存储容量、可视区域和固件清单，具备发展为独立硬件兼容目录的基础。

## 17. 主要缺口和风险

### 17.1 交互方案持久化

交互状态图需要与设计文档形成更稳定的一体化项目模型，理想结构为：

```text
设计项目
├── 画面节点
├── 设备目标信息
├── 交互状态图
├── 屏幕适配配置
└── 最近部署信息
```

否则容易出现关闭后丢失、Frame ID 变化后失效、跨机器复制不完整，以及 CLI/MCP 无法完整管理交互等问题。

### 17.2 真机验收弱于逻辑测试

当前已具备编码、协议、固件流程和状态机单元测试，但以下内容仍高度依赖真实设备：

- USB 重启后的枚举和重连。
- BLE 长时间和大文件传输。
- Flash 擦写、校验和断电恢复。
- 控制器颜色、方向和偏移。
- 触摸和 BOOT 事件识别。
- 特殊电源和复位时序。
- 大序列持续播放帧率。
- 传输中断恢复。

“源码支持”和“发布级验证”需要继续明确区分。

### 17.3 profile 与固件的编译期耦合

当前大致流程为：

```text
profile.defaults
  → 生成 sdkconfig
  → 编译对应固件
  → 生成 manifest
  → 前端按 profile 查找固件
```

这会导致新增屏幕需要重新编译、自定义方案无法直接使用，以及固件数量持续增长。

目标形态应逐步演进为：

```text
选择硬件平台固件
  → 固件上报控制器和总线能力
  → 前端发送运行时屏幕配置
  → 设备验证配置
  → 初始化对应驱动
```

特殊电源、复位和 TE 同步仍可保留平台适配层。

### 17.4 动态 UI 能力不足

当前产品适合预渲染画面和有限状态切换，但动态数据、局部刷新、条件逻辑和运行时控件尚未成为正式能力。这限制了其从交互原型工具向正式嵌入式应用平台扩展。

### 17.5 产品文档存在双重叙事

部分文档仍以 OpenPencil 通用设计器为主，README 已转向 OP Embedded Studio。需要进一步区分：

- 继承自 OpenPencil 的通用能力。
- OP Embedded Studio 独有的嵌入式能力。
- 上游路线与本项目路线。
- 已验证功能与仅有源码支持的功能。

## 19. 建议的功能优先级

### 19.1 P0：核心闭环可靠性

1. 交互方案随设计文档可靠保存和恢复。
2. 完善 USB 中断、重连和重试流程。
3. 完善固件与前端协议版本管理。
4. 增加内容写入后的校验和必要回读。
5. 为每台内置设备标记发布级验证状态。
6. 完成首次连接和故障诊断向导。
7. 将硬件验收整理为可重复执行的测试清单。

### 19.2 P1：降低新增硬件成本

1. 将 GPIO、方向、偏移和颜色顺序迁移为运行时配置。
2. 建立设备能力发现协议。
3. 按硬件平台而不是屏幕型号发布固件。
4. 在 UI 中校验 profile 与固件能力兼容性。
5. 提供屏幕测试图、色彩测试和触摸测试向导。
6. 让 profile 管理器生成可部署配置包。

### 19.3 P2：升级为有限动态 UI 运行时

建议从受控变量系统开始：

- 动态文本变量。
- Number、Boolean、String 和 Color 变量。
- 设备或主机数据绑定。
- 定时器事件。
- 条件跳转。
- 简单表达式。
- 串口数据输入。
- 局部区域重绘。

示例：

```text
设备变量 temperature: number
  → 绑定设计中的温度文本
  → 传感器更新 temperature
  → 设备局部重绘文本区域
```

### 19.4 P3：正式应用交付

后续可提供两条清晰区分的交付路径：

| 路径 | 优势 | 适用场景 |
| --- | --- | --- |
| 通用内容固件 | 上手快、所见即所得 | 原型、展示、静态产品 |
| 原生代码生成 | 动态能力强、可深度集成 | 量产应用和复杂业务 |

原生输出可逐步探索 LVGL/C/C++ 工程生成，但不宜与通用内容部署混成同一个模糊入口。

## 21. 结论

OP Embedded Studio 已经形成一条具有差异化价值的嵌入式设计链路：

```text
可编辑设计
  + 交互状态机
  + 真实设备模拟
  + 通用内容固件
  + USB/BLE 快速部署
  + AI 与自动化
```

其核心优势不是单独某个设计或烧录功能，而是将设计、原型和真机验证合成一个闭环，大幅缩短嵌入式屏幕 UI 的迭代路径。

现阶段最准确的判断是：

> 项目已经是可用于真实 ESP32 屏幕设计和部署的垂直工具；距离可规模化适配硬件、承载正式动态应用的通用嵌入式 UI 平台，还需要补齐设备可靠性、运行时配置、动态数据和项目持久化能力。
